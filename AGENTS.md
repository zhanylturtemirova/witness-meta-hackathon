# Working on Witness

Read README.md, docs/hackathon-scope.md, and docs/meta-models.md first.

- Write project documentation in English. Keep it natural, concise, and useful. Avoid dated status reports and administrative filler.
- Witness is about personal reflection, stories being heard, and connections through shared experiences. Do not reduce it to biography storage.
- Keep the core build focused on a text interview, review, an editable story, and export. Connect is an authorised preview with a globe and fictional matching events. Real auth and community (profiles, messaging, publishing) are now authorised work: see the active plan in [docs/working-app-plan.md](docs/working-app-plan.md).
- Describe planned features as plans. Do not claim integrations, user results, or tests that do not exist.
- Preserve the narrator's voice, uncertainty, and links to source answers. Never invent life events or quotes.
- Use fictional demo stories. Keep real interviews, personal records, and API keys out of Git. Keep API keys on the server.
- Check local document links after edits. Once code exists, document real setup commands and run checks relevant to the changes.
- The active build sequence and acceptance gates live in [docs/working-app-plan.md](docs/working-app-plan.md). Earlier plans in `docs/` are context; point current work at the active plan.
- Build the complete journey incrementally: guest-first interview, source-grounded review, story/events, approved cartoon adaptation, Connect over the globe, saved phrases, likes. Offer account creation after the first story while preserving guest work.
- Never fake authentication or community: no invented accounts, totals, or shared backends before real configuration and tests. Local likes and saved phrases are explicitly on-device.
- All AI product tasks use the existing Meta/Muse adapters; no weight training, no substitute APIs. Muse Image returns images, never motion video; describe the cartoon film honestly. No paid generation calls without explicit authorisation.
- Supabase (Free plan) is the default recommendation for accounts, database, and media; Clerk is the documented alternative. No account creation, upgrades, or remote changes until the project maintainer provides configuration.
- Keep project documentation free of conversational provenance and machine-specific details: no approval or assignment narration, no personal machine paths, no private reference file locations, and no external reference media beyond legally required asset attribution (such as NASA imagery credits) and useful API documentation links.
